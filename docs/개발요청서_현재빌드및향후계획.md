- 보강 요청 월 2회 제한 및 상대방 승인 흐름

### 2.6 급여·재무 관련 최근 수정

- 완료 수업의 실제 `durationMinutes`를 합산한 뒤 최종 반올림하도록 수정
- 10회 × 20분이 `2.999999...h`로 표시되지 않고 3.0h 기준으로 검증되도록 개선
- 선생님·관리자 급여 월 목록에 실제 완료 수업 월을 포함
- 첫 수업 직후 만근/분기 보너스가 생성되지 않도록 자격 조건 검증
- 중국 학생 수강료는 관리자 입금 확인 시점의 CNY→KRW 환율을 적용
- 원금액, 환산금액, 적용 환율·출처·시각을 재무 거래에 기록하는 구조 추가
- 수기 비용 등록은 공급가액이 아니라 결제 총액을 입력하고, 과세 비용은 공급가액·부가세를 역산

### 2.7 운영 이전·성능·인증 관련 최근 수정

- Supabase 데이터를 구 프로젝트에서 신규 싱가포르 프로젝트로 이전
- 운영·로컬 애플리케이션의 Supabase 연결을 신규 프로젝트로 전환
- 공개 페이지의 반복 전체 bootstrap과 모든 강사 availability 선조회 제거
- 선택한 강사의 가능 시간은 수강신청 시점의 필요 기반 조회로 변경
- 관리자 페이지의 중복·전체 DB 조회와 불필요한 재검증 요청 축소
- API 응답의 열 제한, 서버 필터, 요청 중복 제거로 PostgREST Egress 감소
- migration `039`로 Auth refresh token sequence/PK 충돌 복구
- migration `040`으로 `auth.users` → `public.profiles` 생성 트리거 복구 및 누락 프로필 backfill
- 프로필 UPDATE 0건을 성공 처리하던 회원가입 결함 수정
- 학생·선생님 회원가입에서 프로필 누락을 안전하게 자동 복구하되 기존 역할은 덮어쓰지 않도록 보강
- 모바일 공개 페이지 메뉴를 독립 오버레이로 개선하고 로그인·언어 선택 접근성 개선
- 채팅 목록의 계정·inbox 중복 요청 제거와 반응형 알림 벨 단일 실행
- 전체 채팅 메시지 bootstrap을 사용자 범위 DB 집계로 교체하는 migration `041` 운영 적용
- 채팅 API 요청 역할과 실제 로그인 역할을 대조하여 역할 위조 차단

### 2.9 PWA 로그인 세션 유지 (2026-09-05 운영 배포 완료)

- Supabase 인증 쿠키를 30일 `Max-Age`, 전체 경로, Lax, 운영 HTTPS 정책으로 통일하고 로그아웃용 즉시 삭제는 보존
- middleware의 토큰 갱신·삭제 쿠키가 권한 오류/로그인 리다이렉트 응답에서도 브라우저로 전달되도록 보강
- PWA `start_url`을 전용 쿼리 진입점으로 구분하고 `/`에서 유효 세션을 학생·선생님 역할별 포털로 자동 연결
- 일반 공개 페이지는 기존대로 인증 조회를 생략하여 추가 Supabase 트래픽 방지
- 운영 HTTPS에서 학생·선생님 PWA 재실행, 30일 쿠키, 만료 access token 자동 갱신을 종단간 검증
- 구성과 검증 절차: [PWA 로그인 세션 유지](pwa-session-persistence.md)

### 2.10 모바일 PWA 설치·알림 UX 개선 (2026-09-05)

- PC/일반 데스크톱 브라우저에서는 홈 화면 설치와 채팅·수업 알림 설정 UI를 숨기고, Android·iPhone·iPadOS 데스크톱 모드에서만 제공
- 공개 페이지는 강제 스낵바 대신 헤더 메뉴에서 설치 안내에 접근하고, 학생은 `내 정보 관리`, 선생님은 `My Profile`에서 설치 메뉴를 계속 사용할 수 있도록 구성
- 설치 가능한 브라우저는 저장된 `beforeinstallprompt`를 실행하고, iOS·수동 설치 환경은 플랫폼별 브라우저 메뉴 안내를 표시
- 스낵바 닫기는 7일 동안만 임시 배제하며, 설정·프로필의 설치 메뉴에는 영향을 주지 않음. Standalone으로 실행 중인 이미 설치된 앱은 설치 UI를 숨김
- 푸시 권한 거부 상태와 PWA 설치 UI를 분리하여, 알림 권한을 거부해도 앱 설치 안내는 유지
- 설치 메뉴는 브라우저 상태와 로컬 저장소만 사용하며 Supabase 요청을 추가하지 않음
- PWA 모의 테스트·PC/모바일 분기 테스트·TypeScript 검사·production build 통과
- 구현 상세: [PWA/Push 운영 메모](pwa-push.md)

- 관리자 재무 요약 API(`GET /api/admin/finance/summary`)
- 한국·중국 현지 네트워크와 PWA/Web Push 실기기 지속 검증

## 4. 권장 작업 순서

1. 작업 시작 시 `AI_GUIDE.md`와 실제 대상 Supabase URL을 확인
2. 회원가입·로그인·역할별 접근과 핵심 사용자 흐름을 운영 회귀 테스트
3. Egress와 PostgREST timeout을 API별로 계측하고 재발 방지 테스트 유지
4. 급여·노쇼·재무 거래의 수치 대조표 작성
5. 한국/중국 시간대와 다국어 화면 검증
6. production build/start 및 한·중 실제 네트워크 성능 검증
7. 남은 P2 기능을 별도 요구사항으로 분리하여 구현

각 테스트는 실행일, 커밋 ID, 대상 Supabase project ref, DB migration 버전, 결과 로그를 함께 기록한다. 실패 시 시드 문제·환경변수 문제·코드 문제를 구분하여 기록한다. `seed:e2e`는 운영 DB에서 실행하지 않는다.

## 6. 변경 원칙

- 공개 URL, API 응답 구조, 사용자 화면 동작을 임의로 변경하지 않는다.
- 기존 사용자 데이터와 사용자 변경사항을 보존한다.
- DB 스키마 변경은 새 migration으로 추가하며 기존 적용 migration을 재작성하지 않는다.
- DB 스키마 변경과 패키지 제거는 별도 작업으로 분리한다.
- 환율·급여·세무 데이터는 거래 시점 값을 보존하고 사후 재계산하지 않는다.
- 삭제 전 정적 참조, 동적 import, 라우팅, 번역 키, API 및 DB 사용 여부를 확인한다.
- 커밋·푸시·DB 적용·배포 권한을 구분하고 사용자가 요청하지 않은 외부 변경은 수행하지 않는다.
- 운영 인프라·Supabase project ref·도메인·migration 기준이 변경되면 `AI_GUIDE.md`와 본 문서를 같은 작업에서 갱신한다.
