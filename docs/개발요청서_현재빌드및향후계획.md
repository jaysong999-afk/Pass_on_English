# PassOn English 개발요청서

## 1. 문서 목적

현재까지 구현·수정된 기능과 남은 검증 및 개발 작업을 한 문서에서 관리한다. 사용자 화면과 기존 API 계약을 유지하며, 각 후속 작업은 독립적으로 테스트 가능한 단위로 진행한다.

기준일: 2026-08-20  
프로젝트: PassOn English  
기술 스택: Next.js App Router, TypeScript, Supabase, PostgreSQL, Tailwind CSS, next-intl, PWA/Web Push

## 2. 현재까지 빌드된 사항

### 2.1 기본 서비스 및 포털

- 한국어·중국어 랜딩페이지 및 학생 포털
- 영어 기반 선생님 포털
- 한국어 관리자 포털
- 학생·선생님·관리자 인증 및 역할별 라우팅
- 학생 수강신청, 재수강, 계좌이체 입금 신고·관리자 확인 흐름
- 학생·선생님 일정, 수업 완료, 피드백, 수업 로그
- PWA 설치 안내 및 Web Push 기반 알림 구조

### 2.2 학생 기능

- 학생/학부모 회원가입 및 자녀 연결
- 내 정보 관리: 이메일·본명 읽기 전용, 휴대폰·국가 수정, 시간대 자동 매핑
- 자녀 다중 지원 및 English Name 수정
- 성별, 기타메모, 수강목적 저장 및 관리자·선생님 카드 연동
- ZOOM/VOOV 복수 선택
- 수업 가능한 플랫폼을 기준으로 선생님 매칭
- 선생님·관리자와의 채팅
- 수업 캘린더 및 중국어/한국어 날짜·시간 표시
- 선생님 Availability 기반 보강 시간 선택
- 보강 요청 월 2회 제한 및 상대방 승인 흐름
- 수강 기간, 잔여 수업, 노쇼 보강 수업 표시
- 교재·진도·숙제 및 과거 교재 이력 확인

### 2.3 선생님 기능

- 선생님 회원가입 및 공개 프로필
- 개인정보 관리 페이지
- 사용 가능한 ZOOM/VOOV 선택
- Availability와 일정 캘린더
- 신규 수업 알림, 무료체험 `NEW` 표시, 알림 확인 처리
- 학생·관리자 채팅
- 수업 완료 및 피드백 작성
- 학생별 교재·진도·특이사항 입력
- 월별 급여 조회
- 급여 계산 항목: 완료 수업, 만근 보너스, 분기 보너스, 기타 보너스, 공제

### 2.4 관리자 기능

- 학생·선생님 현황 및 상세 프로필
- 학생의 성별·기타메모·수업목적·플랫폼 확인
- 수업별 교재·진도와 과거 교재 이력 확인
- 수업 운영 센터와 주간 스케줄
- 학생↔선생님 보강 요청 모니터링
- 관리자 예외 조치: 일정 변경, 대체 선생님, 노쇼, 무급 취소
- 노쇼 시 보강 수업 생성 및 계약 회차 반영 로직
- 운영 로그 및 취소/복구 이력
- 관리자 메시지·CS 센터
- 요금제 관리
- 선생님 급여 관리 및 정산
- 재무 대시보드, 거래 내역, CSV 다운로드, 수기 거래 등록

### 2.5 리팩터링 및 안정성 개선

- 인증 회귀 테스트 기반과 기본 거부 권한 정책
- 선생님 프로필 API의 권한 및 DTO 제한
- 읽기 부트스트랩과 상태 변경 작업 분리
- fallback/demo 데이터 격리
- 도메인별 cache/store/store-sync 축소
- API client·오류·로딩 처리 통합
- 대형 컴포넌트 및 AppShell·채팅 UI 중복 축소
- DB 타입과 데이터 변환 정리
- 다국어·SEO·서버 컴포넌트 경계 개선
- RLS 및 트랜잭션 경계 보강
- Hydration 오류 수정: `p` 내부에 `div`를 렌더링하던 Badge 사용 방식 개선

### 2.6 급여·재무 관련 최근 수정

- 완료 수업의 실제 `durationMinutes`를 합산한 뒤 최종 반올림하도록 수정
- 10회 × 20분이 `2.999999...h`로 표시되지 않고 3.0h 기준으로 검증되도록 개선
- 선생님·관리자 급여 월 목록에 실제 완료 수업 월을 포함
- 첫 수업 직후 만근/분기 보너스가 생성되지 않도록 자격 조건 검증
- 중국 학생 수강료는 관리자 입금 확인 시점의 CNY→KRW 환율을 적용
- 원금액, 환산금액, 적용 환율·출처·시각을 재무 거래에 기록하는 구조 추가
- 수기 비용 등록은 공급가액이 아니라 결제 총액을 입력하고, 과세 비용은 공급가액·부가세를 역산

## 3. 현재 확인이 필요한 사항

### P0 — 배포 및 데이터 정합성

1. **Supabase migration 038 적용**
   - 대상: `finance_transactions.exchange_rate*` 컬럼
   - 미적용 시 `column finance_transactions.exchange_rate does not exist` 오류 발생
   - 적용 명령: `npx supabase db push`

2. **원격 DB RLS·스키마 적용 여부 확인**
   - migration 026~038 적용 상태 확인
   - Supabase SQL Editor 또는 CLI 결과 기록

3. **E2E 시드 초기화 재검증**
   - `npm run seed:e2e`가 기존 테스트 enrollment의 FK 제한으로 실패할 수 있음
   - E2E 계정과 연결된 수동 enrollment를 확인한 뒤 데이터 정리 정책 결정

### P1 — 핵심 사용자 흐름 회귀 테스트

- 회원가입·로그인·로그아웃·역할별 접근 제어
- 학생 수강신청 → 무료체험 → 입금 확인 → 수업 활성화
- 재수강 신청 및 기존 수강기간과의 연속성
- 학생/선생님 보강 요청 → 상대방 승인/거절 → 일정 반영
- 관리자 노쇼 처리 → 마지막 회차 보강 생성 → 취소/복구
- 수업 완료 → 피드백 → 급여 반영 → 관리자 정산 → 재무 거래 생성
- ZOOM/VOOV 플랫폼 교집합 매칭
- 한국어·중국어 날짜, 시간대, 오전/오후 표시
- 학생·선생님·관리자 채팅 및 프로필 이미지 표시

### P2 — 운영 완성도

- 자동 시스템 알림 cron/Edge Function
- 수업 10분 전·입금 확인·보강 승인·수강 만료 알림
- `teacher_availability_exceptions` UI
- PG 결제, SMS OTP, Zoom/VOOV SDK 연동
- 관리자 재무 요약 API(`GET /api/admin/finance/summary`)
- 홍콩 리전 배포와 중국 현지 네트워크·PWA 실기기 검증

## 4. 권장 작업 순서

1. 원격 Supabase migration 적용 및 스키마/RLS 점검
2. 시드 데이터를 초기화하고 표준 E2E 계정으로 회귀 테스트
3. HTTP API 테스트와 핵심 브라우저 E2E 재실행
4. 급여·노쇼·재무 거래의 수치 대조표 작성
5. 한국/중국 시간대와 다국어 화면 검증
6. production build/start 성능 검증
7. 남은 P2 기능을 별도 요구사항으로 분리하여 구현

## 5. 실행·검증 명령

```powershell
npm run build
npm run start
npm run test:auth:default-deny
npm run test:transactions
npm run test:api:e2e
npm run test:rls
npm run seed:e2e
```

각 테스트는 실행일, 커밋 ID, DB migration 버전, 결과 로그를 함께 기록한다. 실패 시 시드 문제·환경변수 문제·코드 문제를 구분하여 기록한다.

## 6. 변경 원칙

- 공개 URL, API 응답 구조, 사용자 화면 동작을 임의로 변경하지 않는다.
- 기존 사용자 데이터와 사용자 변경사항을 보존한다.
- DB 스키마 변경과 패키지 제거는 별도 작업으로 분리한다.
- 환율·급여·세무 데이터는 거래 시점 값을 보존하고 사후 재계산하지 않는다.
- 삭제 전 정적 참조, 동적 import, 라우팅, 번역 키, API 및 DB 사용 여부를 확인한다.
