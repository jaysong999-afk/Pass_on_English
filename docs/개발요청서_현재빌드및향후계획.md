# PassOn English 개발요청서

## 1. 문서 목적

현재까지 구현·수정된 기능, 운영 인프라와 남은 검증 및 개발 작업을 한 문서에서 관리한다. 사용자 화면과 기존 API 계약을 유지하며, 각 후속 작업은 독립적으로 테스트 가능한 단위로 진행한다.

> AI 작업의 최우선 운영 SSOT는 루트 [`AI_GUIDE.md`](../AI_GUIDE.md)다. 이 문서와 운영 대상 정보가 충돌하면 `AI_GUIDE.md`를 우선하고 두 문서를 함께 정정한다.

기준일: 2026-09-01
프로젝트: PassOn English  
기술 스택: Next.js App Router, TypeScript, Supabase, PostgreSQL, Tailwind CSS, next-intl, PWA/Web Push

### 2.6 급여·재무 관련 최근 수정

- 완료 수업의 실제 `durationMinutes`를 합산한 뒤 최종 반올림하도록 수정
- 10회 × 20분이 `2.999999...h`로 표시되지 않고 3.0h 기준으로 검증되도록 개선
- 선생님·관리자 급여 월 목록에 실제 완료 수업 월을 포함
- 첫 수업 직후 만근/분기 보너스가 생성되지 않도록 자격 조건 검증
- 중국 학생 수강료는 관리자 입금 확인 시점의 CNY→KRW 환율을 적용
- 원금액, 환산금액, 적용 환율·출처·시각을 재무 거래에 기록하는 구조 추가
- 수기 비용 등록은 공급가액이 아니라 결제 총액을 입력하고, 과세 비용은 공급가액·부가세를 역산

### 2.7 운영 이전·성능·인증 관련 최근 수정

- Supabase 데이터를 구 프로젝트에서 신규 싱가포르 프로젝트로 이전
- 운영·로컬 애플리케이션의 Supabase 연결을 신규 프로젝트로 전환
- 공개 페이지의 반복 전체 bootstrap과 모든 강사 availability 선조회 제거
- 선택한 강사의 가능 시간은 수강신청 시점의 필요 기반 조회로 변경
- 관리자 페이지의 중복·전체 DB 조회와 불필요한 재검증 요청 축소
- API 응답의 열 제한, 서버 필터, 요청 중복 제거로 PostgREST Egress 감소
- migration `039`로 Auth refresh token sequence/PK 충돌 복구
- migration `040`으로 `auth.users` → `public.profiles` 생성 트리거 복구 및 누락 프로필 backfill
- 프로필 UPDATE 0건을 성공 처리하던 회원가입 결함 수정
- 학생·선생님 회원가입에서 프로필 누락을 안전하게 자동 복구하되 기존 역할은 덮어쓰지 않도록 보강
- 모바일 공개 페이지 메뉴를 독립 오버레이로 개선하고 로그인·언어 선택 접근성 개선
- 채팅 목록의 계정·inbox 중복 요청 제거와 반응형 알림 벨 단일 실행
- 전체 채팅 메시지 bootstrap을 사용자 범위 DB 집계로 교체하는 migration `041` 작성(운영 미적용)
- 채팅 API 요청 역할과 실제 로그인 역할을 대조하여 역할 위조 차단

### 2.8 PWA 및 일반 채팅 Push 개선 (2026-09-03 로컬 구현, 운영 미배포)

- 공개 랜딩은 설치 가능 이벤트가 있을 때만 작은 버튼 노출; 포털은 설치 카드와 명시적 알림 켜기 버튼 제공
- 설치 이벤트를 공통 Provider에서 저장하고, 닫기 후 7일 숨김·Standalone·권한 거부·iOS 안내 분기 처리

- 학생↔선생님 및 관리자 일반 채팅은 저장 성공 후 서버가 실제 수신자를 조회하여 Push 발송
- migration `043`: 사용자·채팅방·탭 단위 90초 접속 lease로 보고 있는 채팅방의 Push 생략; 숨김/이탈 시 갱신 중단
- 알림 사용자 확인의 전역 bootstrap 제거, 읽음 처리를 서버 필터 단일 UPDATE로 변경
- 목록과 알림 벨의 Realtime 공유, 숨김 시 연결 해제, 정상 연결 중 폴링 중단, 재연결 시 동기화

- 운영 DB에 CLI migration 이력 테이블이 없으므로 과거 migration 일괄 재적용 금지. CLI 연결의 구 프로젝트 참조는 싱가포르로 수정 완료. 상세 기록은 `docs/pwa-push.md` 참고

## 3. 현재 확인이 필요한 사항

### P0 — 운영 안전성과 데이터 정합성

1. **신규 싱가포르 프로젝트만 사용**
   - 코드·로컬 환경·Tencent `.env.production`의 URL과 키가 모두 `mvngtkoqjejvwygikvhi` 프로젝트 쌍인지 유지
   - 구 프로젝트 `yldtimpsgumheiahcwwi`가 런타임 설정에 발견되면 배포 중단

2. **회원가입 운영 회귀 확인**
   - 신규 학생 가입 시 `auth.users`·`profiles`·`students`가 같은 사용자 관계로 생성되는지 확인
   - 신규 선생님 가입 시 `profiles(role=teacher)`와 신청 데이터 관계 확인
   - 기존에 Auth만 생성됐던 계정의 재시도 복구 흐름 확인

3. **Egress·PostgREST timeout 추세 관찰**
   - Supabase Usage 반영 지연을 고려하여 최소 24시간 단위로 비교
   - 일일 총량뿐 아니라 API별 호출 횟수, 응답 크기, timeout 로그를 함께 확인
   - 공개 페이지·관리자 페이지에서 전체 테이블 재조회나 짧은 polling이 재도입되지 않았는지 회귀 점검

4. **E2E 시드 안전성 재검증**
   - 운영 DB에는 명시적 승인 없이 `seed:e2e`를 실행하지 않음
   - 테스트 계정과 연결된 수동 enrollment의 FK 관계를 확인한 후 정리 정책 결정

## 5. 실행·검증 명령

```powershell
npm run build
npm run start
npm run test:auth:signup
npm run test:auth:default-deny
npm run test:auth:teacher-profile
npm run test:transactions
npm run test:api:e2e
npm run test:rls
npm run seed:e2e
```

각 테스트는 실행일, 커밋 ID, 대상 Supabase project ref, DB migration 버전, 결과 로그를 함께 기록한다. 실패 시 시드 문제·환경변수 문제·코드 문제를 구분하여 기록한다. `seed:e2e`는 운영 DB에서 실행하지 않는다.

## 6. 변경 원칙

- 공개 URL, API 응답 구조, 사용자 화면 동작을 임의로 변경하지 않는다.
- 기존 사용자 데이터와 사용자 변경사항을 보존한다.
- DB 스키마 변경은 새 migration으로 추가하며 기존 적용 migration을 재작성하지 않는다.
- DB 스키마 변경과 패키지 제거는 별도 작업으로 분리한다.
- 환율·급여·세무 데이터는 거래 시점 값을 보존하고 사후 재계산하지 않는다.
