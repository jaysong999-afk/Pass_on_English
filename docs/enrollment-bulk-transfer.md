# 수강 일괄 이관 개선 — 2026-09-06

상태: 로컬 구현·검증 완료. migration 044는 2026-09-06 싱가포르 운영 DB에 적용했고, 앱 코드는 커밋·이미지 빌드 후 운영 배포 예정이다.

## 변경 내용

- `/api/admin/lessons/bulk-reassign`는 전체 캐시 초기화를 호출하지 않는다. 목록은 출발 선생님의 활성 계약만, 미리보기·실행은 전달한 계약만 DB RPC로 처리한다.
- 미리보기와 실행은 `admin_transfer_batch`의 동일한 검증을 사용한다. 선생님 활성 상태, Availability 전체 20분 블록, 휴무일, 계약의 정기 시간, 실제 예약·계약 예약·동일 배치 충돌을 검사한다.
- 미래 예정 수업 수와 잔여 회차가 일치하고, 과거 미처리·다른 담당자의 미처리 수업·진행 중인 보강 요청이 없어야 이관된다. 예정 0개를 전체 가능으로 표시하지 않는다.
- 실행은 최신 DB 상태로 재검증하고 계약·수업·조치 기록을 하나의 트랜잭션으로 저장한다. 실패 시 전체 취소한다. Availability를 자동 활성화하는 복구 함수는 호출하지 않는다.
- 기존 수업 저장 경로에도 선생님 시간 중복 방지 트리거를 적용한다. 기존 데이터는 변경하지 않고 새로운 배정/시간 변경/활성화 시 검증한다. 기존 중복 데이터의 관련 없는 메모 수정 등은 허용한다.
- UI는 확인 중·확인 실패·이관 불가 사유를 구분한다. 새 선생님을 선택하면 이전 결과는 즉시 무효가 되며, 모든 수강이 검증을 통과해야 실행할 수 있다. 새로고침은 일괄 이관 목록을 다시 조회한다.

## 트래픽과 동시성

- 목록/미리보기/실행 각각 RPC 1회. Availability·전체 수업 테이블을 브라우저나 앱 서버로 내려받지 않는다. 조회는 출발/도착 선생님과 선택한 계약의 인덱스를 사용한다.
- 미리보기는 250ms debounce와 AbortController를 사용한다. 이미 서버에 도착한 요청까지 취소된다고 가정하지 않으며, 응답 키로 오래된 결과도 배제한다. 백그라운드 폴링은 추가하지 않는다.
- 요청당 최대 100계약·미처리 수업 2,000개를 허용한다. 반환은 건수·차단 사유 및 변경 ID 위주이며, 커밋 후 이미 로딩된 관련 캐시만 수정한다.
- 실행 시 관련 테이블의 쓰기를 짧게 직렬화한다(`SHARE ROW EXCLUSIVE`, 잠금 대기 3초). 일반 조회는 가능하나 다른 선생님의 쓰기도 일시 대기할 수 있다. 기존 쓰기 경로가 공통 잠금 규칙을 사용하지 않기 때문에 정확성을 우선한 초기 방식이다. 동시 운영량이 커지면 관련 계약/가용 시간/수업 쓰기 모두에 선생님별 잠금 규칙을 적용한 뒤 테이블 잠금을 축소해야 한다.
- 수업 쓰기 트리거는 선생님별 advisory lock 및 DB 중복 검사를 사용한다. 이관 전에 조회한 오래된 요청이 이관 후 겹치는 수업을 저장하는 것도 차단한다. 잠금 경합·교착 상태는 DB 오류로 전체 원복되며, 앱은 재확인을 안내한다.

## 배포 순서 (migration 적용 완료, 앱 배포 대기)

1. `AI_GUIDE.md`에 따라 실제 운영 DB가 싱가포르 대상인지 확인했다.
2. `supabase/migrations/044_atomic_enrollment_transfer.sql`만 별도로 적용했다. 전체 `db push`는 사용하지 않았다. 함수 존재, authenticated 실행 권한, anon 실행 거부, 중복수업 방지 trigger를 읽기 전용으로 확인했다.
3. admin RPC의 권한과 기존 수업 생성·보강·대체 배정의 충돌 처리 회귀를 로컬 분리 DB에서 검증했고 새 앱을 커밋·빌드 후 배포한다.
4. 044가 없는 DB에서는 새 API가 오류로 차단된다. 이전 캐시 기반 강제 이관으로 fallback하지 않는다.
5. ET 비활성 시간, 전체 정상 시간, 계약 불일치 사례를 운영 화면에서 미리보기로 확인한다. 실제 이관은 승인된 대상만 실행한다.
